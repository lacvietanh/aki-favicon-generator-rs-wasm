# Functional Feature Set & Artifact Matrix

This document defines the functional outputs, resolution boundaries, and design rationales for the core artifact set generated by the system. The output is strictly bounded to **4 image files + 1 manifest**, representing the universal minimum set required for modern PWA and cross-browser deployment.

---

## 1. Core Artifact Matrix

| Artifact | Format / Size | Target Pipeline | Role / Target Platform | Technical Rationale |
|:---|:---|:---|:---|:---|
| **`favicon.ico`** | ICO container embedding:<br>- `16×16`<br>- `32×32` | **Favicon Pipeline**:<br>Transparent background, 16% rounded-corner mask. | Desktop browser tabs, legacy desktop bookmarks. | Both resolutions are embedded in a single file to prevent fuzzy browser-side interpolation. SVG is omitted to minimize runtime code footprint. |
| **`icon-192.png`** | PNG<br>`192×192` | **App Icon Pipeline**:<br>Original transparency preserved. | PWA general icon, Android fallback. | Declared in manifest with `"purpose": "any"`. Serves as a high-fidelity fallback when masking is not requested. |
| **`icon-512-maskable.png`** | PNG<br>`512×512` | **App Icon Pipeline**:<br>Opaque background, 80% safe zone. | Android Adaptive Icon, PWA Splash Screen. | Declared in manifest with `"purpose": "maskable"`. The opaque canvas and safe-zone margin prevent clipping on shaped launchers. |
| **`apple-touch-icon.png`** | PNG<br>`180×180` | **App Icon Pipeline**:<br>Opaque background, 80% safe zone. | iOS Home Screen Web Clip. | iOS does not read manifest parameters. Needs a fully opaque background (no transparency) to avoid black-background bugs. iOS masks corners automatically. |
| **`manifest.json`** | W3C Web App Manifest JSON | **Metadata Generator** | PWA Installation Metadata. | Registers app identity, theme colors, and maps the 192px and 512px icons to their respective system purposes. |

---

## 2. Manifest Schema Specification

The generated `manifest.json` matches the following schema:
```json
{
  "name": "App Name",
  "short_name": "App",
  "start_url": "/",
  "display": "standalone",
  "theme_color": "#THEME_HEX",
  "background_color": "#BACKGROUND_HEX",
  "icons": [
    {
      "src": "/favicon/icon-192.png",
      "sizes": "192x192",
      "type": "image/png",
      "purpose": "any"
    },
    {
      "src": "/favicon/icon-512-maskable.png",
      "sizes": "512x512",
      "type": "image/png",
      "purpose": "maskable"
    }
  ]
}
```

## 3. Explicit MVP Exclusions

The following outputs are **strictly excluded** from the system implementation boundaries to prevent over-engineering, bloat, or functional overlap:

| Excluded Asset | Technical Reason for Exclusion | Alternative |
|:---|:---|:---|
| **SVG Favicons** | Auto-tracing bitmaps to SVG in browser sandbox requires heavy vector math engines (ballooning WASM/JS package sizes). | If a source SVG is available, reference it manually in HTML `<head>`. |
| **Monochrome Badges** | Only used for Android status bar push notifications. Out of scope for standard browser favicon workflows. | None (Legacy/Specific). |
| **Windows Tile Metadata** | Legacy `browserconfig.xml` and `mstile` sizes are obsolete; modern IE/Edge versions fallback cleanly to standard app icons. | None. |
| **Open Graph Images** | Social sharing images (`1200×630`) require different aspect ratios, marketing designs, and fall under SEO metadata rather than app identity. | Compile manually with standard image editors. |
| **Dark-mode Icon Variants** | Requires multiple input files or programmatic color inversion (which corrupts brand colors). | Link a custom SVG favicon manually with media queries. |
